# POLICE REPORT CENTER — เว็บรวมลิงก์รายงานงาน ป. พร้อมระบบหลังบ้าน

ระบบหน้าเว็บสาธารณะ (`index.html`) + หลังบ้านล็อกอิน (`admin.html`) สำหรับเพิ่ม/แก้ไข/ลบ/จัดลำดับ/ซ่อนปุ่มและหมวดเมนูได้เอง โดยไม่ต้องแก้ไข HTML อีก เชื่อมต่อฐานข้อมูล Supabase ฟรี/ตามแพ็กเกจที่ใช้ และเผยแพร่หน้าเว็บบน GitHub Pages

## สิ่งที่ได้รับ

- หน้าเว็บรวมลิงก์รายงานเดิมทั้ง 6 ลิงก์ แบ่งก่อน 08.00 น. / ก่อน 09.00 น.
- แม่แบบ Canva จุดตรวจสัมพันธ์เวรอำนวยการ อยู่ล่างสุด (รวมเป็น 7 ลิงก์)
- เช็กลิสต์เฉพาะรายการที่เลือกให้นับ, บันทึก **เฉพาะเครื่อง/เบราว์เซอร์นั้น** และเริ่มใหม่ตามวันในเขตเวลาไทย ไม่ใช่สถานะการส่งรายงานจริง
- ระบบหลังบ้าน: เพิ่ม/แก้ไข/ลบปุ่ม; เปิด/ปิดการแสดง; เลือกหมวด; ตั้งชื่อ/URL/คำอธิบาย/ประเภท; กำหนดการนับเช็กลิสต์; เลื่อนลำดับ; เพิ่ม/แก้ไข/ลบ/ซ่อนหมวดและป้ายกำหนดเวลา
- ระบบล็อกอินอีเมล/รหัสผ่าน Supabase Auth และสิทธิ์แอดมินจากฐานข้อมูลเท่านั้น (Row Level Security)

## ขั้นตอนเปิดใช้งานระบบหลังบ้าน (ทำครั้งแรกเท่านั้น)

### 1. สร้างโครงการ Supabase

1. เข้า https://supabase.com/dashboard แล้วสร้าง **project ใหม่** สำหรับเว็บรวมลิงก์นี้ เพื่อไม่กระทบระบบอื่นที่มีอยู่
2. ไปที่ **SQL Editor → New query** คัดลอกเนื้อหาจาก `setup.sql` ไปวางและกด **Run**
3. ตรวจสอบใน **Table Editor** ว่ามีตาราง `report_hub_groups`, `report_hub_links`, `report_hub_admins`
4. ตารางแรกเริ่มมี 3 หมวดและ 7 ลิงก์ รวม Canva ที่ขอเพิ่มล่าสุด

### 2. สร้างบัญชีแอดมินและมอบสิทธิ์

1. ไปที่ **Authentication → Users → Add user** แล้วสร้างบัญชีอีเมลและรหัสผ่านที่ต้องการ (กรุณาใช้รหัสผ่านที่คาดเดายาก)
2. กลับไป **SQL Editor** เรียกคำสั่งนี้ โดย **แทนที่อีเมล** ให้ตรงกับบัญชีที่เพิ่งสร้าง:

```sql
insert into public.report_hub_admins (user_id)
select id from auth.users where email = 'your-admin-email@example.com'
on conflict (user_id) do nothing;
```

3. ถ้าต้องการเพิ่มแอดมินหลายคน ทำขั้นตอนนี้ซ้ำตามแต่ละอีเมล (อย่าเพิ่มข้อมูลส่วนตัวอื่นลงในหน้าเว็บ)
4. ตรวจสอบสิทธิ์:

```sql
select u.email from public.report_hub_admins a
join auth.users u on u.id = a.user_id;
```

**สำคัญ:** ผู้ล็อกอินได้แต่ไม่มีชื่อในตาราง `report_hub_admins` ไม่สามารถแก้ไขเมนูได้ ห้ามเปิดบริการสมัครสมาชิกสาธารณะโดยไม่จำเป็น

### 3. เชื่อมหน้าเว็บกับ Supabase

1. ไปที่ **Project Settings → API Keys** หรือหน้า **Connect** ของโครงการ
2. คัดลอก **Project URL** รูปแบบ `https://xxxx.supabase.co` และ **Publishable key** (หรือ legacy `anon` key ถ้าจำเป็น)
3. เปิดไฟล์ `config.js` แก้เฉพาะค่าที่อยู่ในเครื่องหมายอัญประกาศ:

```js
window.REPORT_HUB_CONFIG = {
  supabaseUrl: 'https://PROJECT-REF.supabase.co',
  supabasePublishableKey: 'sb_publishable_...' 
};
```

**อย่าใส่ `service_role`, `secret key`, รหัสผ่านผู้ใช้ หรือโทเค็นส่วนตัวลงในไฟล์ของ GitHub Pages** เพราะผู้เข้าเว็บสามารถดูซอร์สได้

4. ตรวจสอบว่าใน Supabase **Integrations → Data API → Settings** เปิดใช้งาน Data API และ expose schema `public` (SQL ชุดนี้มี GRANT และ RLS แล้ว)
5. เปิด `index.html` และ `admin.html` ทดสอบเชื่อมต่อ (แนะนำใช้ GitHub Pages หรือ local HTTP server เช่น `python -m http.server 8000`)

### 4. อัปโหลดขึ้น GitHub Pages

1. สร้าง repo ใหม่บน GitHub เช่น `prachinburi-report-hub` (แนะนำอย่าอัปโหลดแฟ้มที่มีข้อมูลลับ)
2. อัปโหลดไฟล์ **ทั้งหมด** ต่อไปนี้ไปที่ root ของ repo:

```
index.html
admin.html
style.css
common.js
main.js
admin.js
config.js
```

3. สำหรับบันทึกการติดตั้ง ควรเก็บ `README.md` และ `setup.sql` ไว้ใน repo ด้วยได้ (ไม่มีรหัสลับในไฟล์ตัวอย่าง)
4. ไปที่ repo → **Settings → Pages → Deploy from a branch → main → / (root) → Save**
5. เปิด URL ที่ GitHub Pages แสดง เช่น `https://USERNAME.github.io/REPOSITORY/`
6. หลังบ้านอยู่ที่ `https://USERNAME.github.io/REPOSITORY/admin.html`

### 5. วิธีเพิ่มปุ่มหรือหมวดเมนูในแต่ละวัน

1. เปิดหน้า `admin.html` แล้วล็อกอินด้วยบัญชีแอดมิน
2. กด **+ เพิ่มปุ่มใหม่** กรอกชื่อ, URL, คำอธิบาย, เลือกหมวด และกดบันทึก
3. ปุ่มจะขึ้นบนหน้า `index.html` ของทุกคนเมื่อโหลดหน้าใหม่ทันที **ไม่ต้อง Commit GitHub**
4. หากยังไม่มีหมวดที่ต้องการ กดแท็บ **จัดการหมวดเมนู → + เพิ่มหมวดเมนู** ก่อน
5. ใช้ปุ่ม ↑ ↓ เพื่อจัดลำดับ; กดแก้ไขเพื่อซ่อนชั่วคราว หรือกดลบเพื่อลบถาวร

## ข้อควรระวัง

- อย่าลบหมวดเมนูถ้ายังมีปุ่มใช้งานอยู่ เพราะการลบหมวดจะลบปุ่มทั้งหมดภายในหมวดนั้นด้วย (ระบบแจ้งเตือนก่อนลบ)
- ถ้าไม่ได้กรอก `config.js` หน้าเว็บ **ยังใช้ 7 ลิงก์เดิมได้ในโหมดตัวอย่าง** แต่หลังบ้านยังไม่สามารถบันทึกหรือเปลี่ยนข้อมูลได้
- รายการบนเว็บเป็นลิงก์ออกไป Google Sheets / Canva / Drive ไม่ได้อ่านข้อมูลรายงานหรือยืนยันสถานะว่าได้ส่งจริง
- การแก้ไขจากหลังบ้านเป็นการเปลี่ยนข้อมูลส่วนกลาง สำหรับผู้ใช้ที่เปิดเว็บแล้วให้รีเฟรชหน้าใหม่เพื่อเห็นรายการล่าสุด
- ผู้เข้าชมต้องมีสิทธิ์ในเอกสาร Google / Canva / Drive ตามที่เจ้าของไฟล์กำหนด
- ระบบใช้ Supabase JS จาก CDN จึงต้องมีอินเทอร์เน็ตเมื่อเชื่อมต่อฐานข้อมูล
- สำหรับการใช้งานในงานราชการ ควรพิจารณานโยบายด้านการจัดเก็บข้อมูล/สิทธิ์ผู้ดูแลและตั้งค่า MFA ให้ผู้ดูแลตามความเหมาะสม

## วิธีทดสอบหลังตั้งค่า

1. เปิด `index.html`: ต้องแสดง 3 หมวด 7 ปุ่ม
2. เปิด `admin.html`: ล็อกอินแอดมินที่ได้รับสิทธิ์แล้ว
3. เพิ่มปุ่มทดสอบ `https://example.com/` ในหมวดแม่แบบ; เปิด `index.html` แล้วรีเฟรช ต้องเห็นปุ่ม
4. กลับไปหลังบ้าน แก้ไขชื่อ ปิดการแสดง แล้วทดสอบปุ่มหายจากหน้าแรก
5. ทดสอบบัญชีอื่นที่ไม่ได้รับสิทธิ์ ไม่ควรเห็นเครื่องมือแก้ไขและไม่สามารถเขียนผ่าน API ได้
6. ลบปุ่มทดสอบเมื่อเสร็จ

## โครงสร้าง

- `index.html` — เว็บรายงาน (อ่านข้อมูล)
- `admin.html` — เว็บจัดการ (ต้องล็อกอิน)
- `style.css` — ธีมทั้งสองหน้า
- `common.js` — config, Supabase client, แหล่งข้อมูลสำรอง, helpers
- `main.js` — แสดงลิงก์และเช็กลิสต์รายวัน
- `admin.js` — จัดการข้อมูลและล็อกอินแอดมิน
- `config.js` — Project URL + **public/publishable** key เท่านั้น
- `setup.sql` — ตาราง RLS และข้อมูลเริ่มต้น 7 ลิงก์
